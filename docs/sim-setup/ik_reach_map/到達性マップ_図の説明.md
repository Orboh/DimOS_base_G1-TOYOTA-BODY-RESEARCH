# ZED画角 × G1右腕 IK到達性マップ — 図の説明

折田（2026-09-15）

添付3枚（`reach_score.png` / `reach_by_distance.png` / `reach_space.png`）が何を計算した結果なのかの説明です。

---

## 何をしたか

**ZEDカメラの画角を10×10に分割し、各セルが指す方向の3D点に G1 の右腕が IK で手を伸ばせるかを総当たりで判定**しました。

画素は「点」ではなく「光線」なので、画角を2D分割しただけでは3D点が決まりません。そこで**カメラからの距離を
0.3 / 0.4 / 0.5 / 0.6 / 0.7 m の5段階でスイープ**し、10×10×5 = **500点**を評価しています。

判定器は既存の `IkApproachSkill`（オクラ収穫パイプラインの Phase B と同じもの）をそのまま使っています。
`None` を返したら「届かない」という、パイプライン本番と同じ基準です。DimOS 側のコードは一切変更していません。

**Isaac Sim は使っていません。** pinocchio + `g1.urdf` の運動学計算だけなので、500点が数秒で終わります。

---

## 計算の条件（結果はこの条件に強く依存します）

| 項目 | 値 | 備考 |
|---|---|---|
| カメラ | 640×360, HFOV 90°（VFOV 58.7°） | sim の `SIM_CAM_HFOV` 既定値 |
| カメラ取付 | torso相対 (0.08, 0, 0.20)、視線 (1, 0, -0.35) | `SIM_CAM_LOCAL_POS` / `SIM_CAM_LOCAL_FWD` の既定値 |
| 対象 | **右腕のみ** | 左腕の IK モデルがリポジトリに無いため |
| 姿勢 | 腰・脚は固定。基準姿勢（全関節0）から**関節デルタ90°以内** | `IkApproachSkill` の既定 |
| ワークスペース箱 | X(0.05, 0.65) Y(-0.75, 0.20) Z(-0.35, 0.85) | この外は IK を解かずに即 NG |
| standoff | 0 m | 目標点そのものに指先を置く設定 |

画素→torso の変換は `sim_dds_bridge.py` の胸カメラ規約（L600 画角 / L617 取付 / L635-674 optical基底 /
L710 焦点距離）に合わせてあり、bridge が publish する `cam_to_torso` と同じ構成です。

IK ソルバが `position_only=True`（`right_arm_model.py:235`）なので、**返る残差は純粋な位置誤差[m]
＝「指先があと何m足りないか」** になります。図の「不足距離」はこの値です。

---

## 図の読み方

### 1. `reach_score.png` — メインの地図

10×10 のマス目がそのまま画角に対応します（**row0 = 画像の上端、col0 = 画像の左端**）。
マスの数字は「**5つの距離のうち何個で手が届いたか**」で、濃いほど良い。`x` は5距離とも届かないセルです。

画像の左側 = ロボットから見て左（torso +Y 側）です。

### 2. `reach_by_distance.png` — 距離ごとの内訳

5つの距離それぞれについて 10×10 の可否を並べたものです。

- `o`（緑）= 届く
- `x`（赤）= IK を解いたが届かない。**マスの色の濃さが不足距離**（濃いほど遠い）
- `/`（灰）= **ワークスペース箱の外なので IK を評価していない**（「届かない」とは別物）

### 3. `reach_space.png` — 空間分布

同じ500点を torso 座標系に置き直した散布図です。**緑の雲が「手が届く範囲」**。

- a) 上から見た図（X前方 × Y左）
- b) 横から見た図（X前方 × Z上）
- c) 3D（緑=到達 / 赤=IKで届かない / 灰=箱の外）

a) と b) は500点を平面に潰しているのでマークが重なります。**「どこに」届く点があるかを見る図**で、
個数の比較は c) と `reach_by_distance.png` の方で見てください。

## 結果

| カメラからの距離 | 到達 | 箱外で即NG | IKで届かずNG | NG時の平均不足 |
|---|---|---|---|---|
| 0.3 m | **80/100** | 20 | 0 | — |
| 0.4 m | **74/100** | 20 | 6 | 5.1 cm |
| 0.5 m | **17/100** | 30 | 53 | 9.3 cm |
| 0.6 m | 0/100 | 65 | 35 | 22.6 cm |
| 0.7 m | 0/100 | 94 | 6 | 46.6 cm |

- **画像の左2列（c0, c1）は全距離で不可。** ワークスペース箱の Y ≤ 0.20 m に引っかかります＝右腕の担当範囲外です。
  画角の左側を扱うなら左腕の IK モデルが要ります。
- **一番余裕があるのは画像中央〜やや右（c5〜c7）の中段（r2〜r6）、距離 0.3〜0.5 m。**
  5距離中3距離で到達し、関節リミットまでの余裕も最大（約1.0 rad）でした。最上位は r6c5 = torso (0.435, -0.040, 0.004) @0.4m。
- 効いているのは**主に左右位置と距離**で、上下（行）による差は小さいです。

---

## 断定できないこと

- **0.6 m 以上が 0% の主因は、腕の限界ではなくワークスペース箱 `ws_x=(0.05, 0.65)` で先に弾かれていること**です（65/100）。
  ただし 0.5 m の時点で IK 残差が平均 9.3 cm あるので、箱を広げても 0.6 m が実用になるとは考えにくいです。
- **腰・脚を固定し、基準姿勢から関節デルタ90°以内**という条件付きの結果です。実機は腰をひねる・前傾するぶん、
  実際の到達範囲はこれより広いはずです。この地図＝ロボットの限界、ではありません。
- 到達率は**カメラの取付・向きに強く依存**します。実機 ZED の取付が sim 既定値と違えば地図も変わります
  （スクリプトの `--cam-pos` / `--cam-fwd` に実測値を入れれば実機向けの地図が出せます）。
- この3枚は「**その座標に指先を置ける関節角が存在するか**」しか見ていません。
  **自己干渉とバランスは判定できていません。**

### 自己干渉については別途確認済み

Isaac Sim（headless）で同じ関節角を実際の G1 USD に入れて確かめました（`isaacSim/` 配下）。

- 指令姿勢がそのまま入った100点では、**指先と目標の距離が中央値 0.1 mm**。URDF と USD の幾何は一致しています
- 接触が検出されたのは 74/171 点ですが、**うち71点はめり込み1mm未満**の convex hull のかすりでした。
  実質的なめり込みは3点のみ（右手と左手の干渉）
- 上の3枚と両方を通ったのは **69/171 点**

## `reach_map.csv` の中身（生データ）

図3枚はすべてこの CSV から描いています。**ヘッダ1行 + 500行**（10×10セル × 5距離）。

| 列 | 意味 |
|---|---|
| `depth` | カメラからの距離[m]（光軸方向） |
| `row`, `col` | 画角10×10のセル番号。**row0 = 画像上端、col0 = 画像左端** |
| `u`, `v` | そのセルの中心画素座標[px] |
| `tx`, `ty`, `tz` | **その画素＋距離が指す3D点の torso 座標[m]**（X前・Y左・Z上）＝ IK の目標点 |
| `reach_ok` | **1 = 手が届く**（これが結論。図の ○× はこの列） |
| `in_ws_box` | 1 = ワークスペース箱の中 / 0 = 箱の外なので IK を解いていない |
| `converged` | IK ソルバが収束したか |
| `err_m` | **位置誤差[m] ＝ 指先があと何 m 足りないか**。0 に近いほど余裕がある |
| `joint_margin_rad` | 関節リミットまでの最小余裕[rad]。大きいほど無理のない姿勢 |
| `max_joint_rad` | 解の関節角の絶対値の最大 |
| `q0`〜`q6` | **IK 解の右腕7関節角[rad]**。並び順は `right_arm_joint_order.txt` |

行は3パターンあります。

```
0.3,0,2,160,18,0.4133,0.15,0.2442,1,1,1,8e-05,1.2716,...,-0.8388,0.3166,...
  → reach_ok=1: 届いた。err=0.08mm、関節余裕1.27rad、q0..q6 に解が入っている

0.3,0,0,32,18,0.4133,0.27,0.2442,0,0,0,,,,,,,,,,
  → in_ws_box=0: 箱の外なので IK を解いていない。以降は空欄

0.4,0,2,160,18,0.5244,0.2,0.259,0,1,0,0.0556,,1.6564,,,,,,,
  → 箱の中だが IK で届かず。err_m=0.0556 ＝ 5.6cm 足りない。q は空
```

`q0`〜`q6` は Isaac Sim 側（自己干渉の確認）へ渡すために入れてあります。

## 再現方法

```bash
cd /isaac-sim/workspace/DimOS_base_G1-TOYOTA-BODY-
.venv/bin/python /isaac-sim/workspace/02_orita_tool/IK_doc/zed_fov_reach_map.py   # 判定＋図1,2
.venv/bin/python /isaac-sim/workspace/02_orita_tool/IK_doc/plot_reach_3d.py       # 図3
```

`--grid 20`、`--depths 0.25,0.35,0.45`、`--cam-pos` / `--cam-fwd` などで条件を変えられます。
全500点の生データ（torso座標・可否・残差・関節余裕・IK解の関節角）は `reach_map.csv` にあります。

ツール一式と詳細は `/isaac-sim/workspace/02_orita_tool/IK_doc/README.md` に置いてあります。
