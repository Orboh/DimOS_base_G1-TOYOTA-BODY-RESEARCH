# 胸ポケットを付けた G1 の 右腕IK 到達性 — 図の説明

折田（2026-09-15）

ポケット無しで出した [到達性マップ](../到達性マップ_図の説明.md) の続きです。
**G1 の胸に四次元ポケットを取り付けた状態**で同じ評価をやり直し、さらに
**Isaac Sim で実際のロボットモデルに当てて確かめる工程**を足しました。

---

## 何をしたか

前回（ポケット無し）は **IK が解けるかどうかだけ**を見ていました。これは
「その座標に指先を置ける関節角が存在するか」という数学的な判定で、
**自己干渉もポケットとの当たりも原理的に判定できません**。

そこで今回は3段構えにしました。

| 段階 | 何を見るか | 環境 |
|---|---|---|
| 1 | IK が解けるか | pinocchio + URDF（Isaac Sim 不要、数秒） |
| 2 | 指令姿勢が実機モデルで再現できるか／自己干渉しないか | Isaac Sim headless |
| 3 | ポケットの空間に腕が入らないか | 同上 |

段階1の判定器は前回と同じ `IkApproachSkill`（収穫パイプラインの Phase B）です。

---

## 取り付けたポケット

| 項目 | 値 |
|---|---|
| 形状 | 正面から見て半円（直径17cm・深さ8.5cm）を前後8cm押し出した半円柱。前後とも板で塞ぎ、開口は上面のみ |
| 外形 | **8.0 × 17.0 × 8.5 cm**（肉厚3mm、内寸 左右164 × 深さ82 mm） |
| 取付位置 | torso_link 相対 **xyz = (+0.0709, 0, +0.0770) m**、回転なし |
| 胴体との関係 | 背面の**上端だけが接触**（めり込み 0 mm） |

⚠️ **平らな背面板は G1 の体に沿いません。** 胴体が下に行くほど細くなるので、
上端で接しても下側は最大 129 mm 離れます。「浮かせず、めり込ませず、全面密着」は
幾何的に不可能です。今回は「一番上だけ接していればOK」という前提で置いています。
実機で固定するなら、背面を胴体曲面に沿わせる／爪で引っ掛ける等の設計変更が要ります。

見た目は `pocket_front.png` `pocket_close.png` `pocket_side.png` `pocket_top.png`。
形が一番分かるのは **`pocket_top.png`（斜め上から）**です。

## 結果

| 段階 | 通過 | 差分 |
|---|---|---|
| IK解析だけ | 171 | — |
| ＋ ロボットモデルの幾何・自己干渉 | 69 | -102 |
| **＋ ポケットとの当たり** | **65** | **-4** |

500点の内訳:

| 状態 | 点数 |
|---|---|
| 到達できる | **65** |
| ポケットに当たる | 50 |
| モデル干渉・姿勢が再現できない | 56 |
| IK が解けない | 100 |
| ワークスペース箱の外（IK未評価） | 229 |

**ポケットが原因で落ちたのは 4 点だけ**です。ポケットに当たる点は 50 点ありますが、
うち 46 点は元々（自己干渉か指先誤差で）落ちていた点でした。

- 当たる場所は **c2〜c5（画角の左寄り〜中央）に集中**。ポケットが胸の中央にあるので、
  腕が体の前を横切るときに当たります。**右寄り（c6〜c9）は無傷**。
- 距離別では **0.3 m が 30/100、0.4 m が 35/100**。近いほどポケットに当たるため、
  0.3 m の方がむしろ少なくなっています。0.5 m 以遠は 0（前回同様、腕が届かない）。
- 指令姿勢がそのまま入った点では、指先と目標の距離が中央値 **0.1 mm**。
  つまり **URDF（pinocchio）と USD（Isaac Sim）の幾何は一致**しています。

## 図の読み方

### 1. `pocket_reach_score.png` — メインの地図

10×10 のマス目が画角に対応（**row0 = 画像上端、col0 = 画像左端**）。数字は
「5つの距離のうち何個で**最後まで通ったか**」。`x` は1つも通らないセルです。

### 2. `pocket_reach_by_distance.png` — なぜ落ちたかの内訳

距離ごとに、各セルが5状態のどれかを色と記号で示します。**色だけでなく記号も見てください**。

| 記号 | 色 | 意味 |
|---|---|---|
| `o` | 緑 | 到達できる |
| `P` | 黄 | ポケットに当たる |
| `X` | 橙 | 自己干渉、または指令姿勢が再現できない（指先誤差 ≥ 5mm） |
| `x` | 赤 | IK が解けない |
| `.` | 灰 | ワークスペース箱の外で IK を評価していない（「届かない」とは別物） |

### 3. `pocket_reach_space.png` — 空間分布

同じ500点を torso 座標に置き直した散布図です。a) 上から / b) 横から（**ポケットの断面を重ねてあります**）/ c) 3D。

上から見た図（a）で、**黄（ポケット）が左寄り、緑（到達）が右寄り**にきれいに分かれるのが分かります。

### 4. `reach_with_pocket.png` — 段階ごとの絞り込み

a) IKのみ → b) +ロボットモデル → c) +ポケット → d) 散布図、の4パネル。
**b と c の差がポケットの影響**です。

## `pocket_reach_map.csv` の中身

500点それぞれの最終判定。

| 列 | 意味 |
|---|---|
| `depth` / `row` / `col` | 距離[m] と 画角セル番号 |
| `tx`, `ty`, `tz` | その点の torso 座標[m]（X前・Y左・Z上） |
| `state` | 上の5状態のどれか |
| `final_ok` | 1 = 最後まで通った |

より詳しい生データ（Isaac 上の指先位置・押し戻し量・接触ペア・めり込み深さ・
ポケット判定点数）は `isaac_verify_with_pocket.csv` にあります。

## 断定できないこと

- **ポケット判定は外形ボリュームに腕の点が入るかで見ています。** 安全側の評価で、
  「ポケットの中に手が入っている」状態も当たりとして数えます。壁の肉厚3mmだけを
  厳密に見たい場合は別途調整が要ります。
- **自己干渉 74 点のうち 71 点はめり込み 1mm 未満**（convex hull 近似でのかすり）です。
  convex hull は実形状より膨らむので、この 65 点は**保守的な下限**と見てください。
  「必ずぶつかる」という意味ではありません。
- **腰・脚を固定し、基準姿勢から関節デルタ90°以内**という条件付きです。実機は腰をひねる・
  前傾するぶん、実際の到達範囲はこれより広いはずです。
- 骨盤固定・重力0で評価しています。**バランスと重力たわみは見ていません。**
- 到達率は**カメラの取付・向きに強く依存**します（sim 既定値で計算）。

## 再現方法

```bash
cd /isaac-sim/workspace/DimOS_base_G1-TOYOTA-BODY-
# 段階1（先に実行して reach_map.csv を作る）
.venv/bin/python /isaac-sim/workspace/02_orita_tool/IK_doc/zed_fov_reach_map.py
# 段階2+3（Isaac Sim headless、ポケット込み）
conda run -n env_isaaclab_2 python /isaac-sim/workspace/02_orita_tool/IK_doc/isaacSim/isaac_reach_verify.py \
    --pocket --pocket-origin 0.0709,0,0.0770 \
    --out /isaac-sim/workspace/02_orita_tool/IK_doc/outAndPocket/isaac_verify_with_pocket.csv
# 図
.venv/bin/python /isaac-sim/workspace/02_orita_tool/IK_doc/outAndPocket/plot_final_maps.py
```

pinocchio が入っているのは dimos 側の `.venv`、Isaac Sim は `env_isaaclab_2` です（環境が別なので2段構成）。
ポケットの位置を変えたら `--pocket-origin` も合わせて変えてください。
ポケット本体の生成・取り付けは `/isaac-sim/workspace/sub/四次元ポケット_CAD/` 側にあります。

**注意**: 自己干渉やポケット当たりが「0件」と出たときは、まず検出が壊れていないか疑ってください。
`isaac_reach_verify.py --selftest` がわざと腕を体にめり込ませて検出を確認するモードです。
実際、この作業中に検出のバグで「0件」を3回誤って出しました（詳細は `README.md`）。
