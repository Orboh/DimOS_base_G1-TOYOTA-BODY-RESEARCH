# クリック→IK切断把持の「ズレ」原因まとめ（誤差予算） — 2026-07-22時点

## TL;DR

観測されたズレは合計 **2〜5cm**。内訳を実測で分解した結果、**上位2項（刃の+4cmと手首姿勢の不定）で
全体の8割**を占めており、両方とも2026-07-21〜22に対策済み。残存誤差は約1〜2cmで、
爪の開口（約4cm）に対して把持可能な水準。

**7/22の10回テストによる裏付け**：対策後の残存ズレは全試行で**2cm以内**（予算表の予測どおり）。
成功3/10で、失敗は「残存ズレが爪開口の境界（1〜2cm）に乗る」か「接近経路上の接触」に二分された。
→ 誤差の分解は完了しており、次の一手は精度でなく**経路**（上からアプローチ）と把持余裕の確保。

「純正カメラ＋純正グリッパなのになぜズレる？」への答え：**URDFは設計値であって個体の実寸ではなく、
工場出荷時にカメラ→指先のハンドアイ校正は行われていない**。産業用ロボットが外さないのは
設置後の校正と治具固定によるもので、部品の純正性は精度を保証しない。

## 誤差の連鎖（どこで生まれるか）

```
クリック（画面）
 → 点群の1点（深度センサの誤差・表面点≠中心）
 → カメラ→胴体変換（URDF設計値 vs 個体実寸）
 → IK解（7自由度の冗長性→手首姿勢の選択）
 → サーボ追従（重力たわみ・定常残差）
 → 工具先端（刃のオフセット）
 → 物理的な着地点
```

## 計測方法論（確立済み）

- **ホバー法**: `OKRA_NOACT_STANDOFF_M=0.05` で狙い点の5cm手前停止 → 刃先〜的の実距離と横ズレを
  的に触れずに読む。奥行き=「実ギャップ−5cm」が工具オフセット誤差
- **2距離判別**: 30cmと50cmで同じ的を計測 → ズレが距離不変=工具オフセット / 距離比例=角度誤差
- **姿勢の比較可能性**: リーチログの手首関節(q[5],q[6])が±0.3rad以内のリーチ同士だけ比較する
  （捻れ姿勢のズレは別物）

## 7/22に追加で判明したハード側の事象（ズレとは別枠）

- **伸ばした姿勢の長時間保持で腕が落ちる**（2.5分保持→指令なしで実測0.87radズレ、電池は正常）
  → モータ過負荷/過熱保護と推定。運用対策=到達後は速やかにホーム戻し（oda/arm_home.py）
- **グリッパモータの無効化が再発**（朝と同日午後の2回目。指令中継されるがtau=0で不動）
  → 復旧手順確立済み: 電源OFF→ハンドコネクタ挿し直し→ON。**毎セッション開始時の生存probe必須**
- **アタッチメント2回目の破損**（7/21・7/22）→ 補強or予備が必要

## 教訓

- **「fix-from-error」で環境変数を回すより、1回の設計された計測**（ホバー法・2距離判別）が速い
- 計測は物理接触を避ける（触った瞬間データが汚れる）
- 冗長自由度のIKは「届く」と「毎回同じように届く」が別物 — 再現性には向きの固定が必須
